# Eiraman

**Traditional management, applied to AI.**

Eiraman is an open method for governing multi-agent AI software development, written for a manager who
is not a developer. AI agents do the work; a named human stays accountable for it. The method borrows
what management already knows: clear mandates, delegation by reversibility (Deny, Delegate, Do), four
eyes on every result, decisions on evidence, and bad news first.

Specialist competence lives in **Role Profiles**, reviewed by domain experts, so a manager does not need
a specialist on every project. **Applicability levels** say how far a project may go, and with which
evidence.

## Status

Early and invitation-only. Every Role Profile is a **draft, not qualified**. Governance is in its first
stage, with an independent Steward; thresholds for a Steering Committee are written in
[GOVERNANCE.md](https://github.com/eiraman/community/blob/main/GOVERNANCE.md).

## Contributing

Start from [PATHWAYS.md](https://github.com/eiraman/community/blob/main/PATHWAYS.md): one path for each kind of
contributor. Every commit carries a DCO sign-off by a person, and every pull request declares how AI was
used ([CONTRIBUTING.md](https://github.com/eiraman/.github/blob/main/CONTRIBUTING.md)). Report
vulnerabilities and unsafe guidance privately ([SECURITY.md](https://github.com/eiraman/.github/blob/main/SECURITY.md)).

The Eiraman name and logo are covered by the
[trademark policy](https://github.com/eiraman/community/blob/main/TRADEMARK.md), not by the content licences.
